# Aegis Universal Execution DAG & Intelligent Scheduler

## 1. Overview & Architecture

The **Execution DAG** transforms the high-level `TestPlan` generated by the Phase 2 Planner into an executable, dependency-ordered directed acyclic graph (`ExecutionDAG`).

Execution follows strict hierarchical gating:

```text
                     ┌──────────────────┐
                     │  SANITY RUNNER   │ (Environment & preflight checks)
                     └─────────┬────────┘
                               │ (gates)
                 ┌─────────────┴─────────────┐
                 ▼                           ▼
        ┌─────────────────┐         ┌─────────────────┐
        │   UNIT RUNNER   │         │   API RUNNER    │ (Contract & Bounded Fuzzing)
        └────────┬────────┘         └────────┬────────┘
                 │                           │
                 └─────────────┬─────────────┘
                               ▼
                    ┌─────────────────────┐
                    │ INTEGRATION RUNNER  │ (Boundary safety check)
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │     E2E RUNNER      │ (User journey orchestration)
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │      UI RUNNER      │ (Visual baseline diffs)
                    └─────────────────────┘
```

## 2. Core Execution Principles

### 2.1 Fast-Fail Cascading & Resource Protection
When an upstream node fails (e.g. Sanity preflight or unit tests):
- All downstream nodes with a hard dependency (`failure_policy="block_dependents"`) are immediately marked `BLOCKED`.
- Their provenance reason records the upstream failure (e.g., `Blocked by upstream failure in sanity.preflight`).
- Independent branches and pure static validations continue execution to gather maximum evidence without wasting compute on doomed runs.

### 2.2 Execution Identity & Multi-Level Caching
Every test node calculates a deterministic execution hash:
$$\text{ExecHash} = \text{SHA256}(\text{NodeID} + \text{TreeHash} + \text{ConfigHash})$$

If the repository state (`tree_hash`) and node configuration remain unmodified and no errors occurred previously:
- The node execution is marked `PASSED (CACHED)`.
- Results are retrieved from `.aegis/cache/execution_cache.json`.

### 2.3 Controlled Retries & Flakiness Classification
Failures are categorized into:
1. `DETERMINISTIC_FAILURE`: Standard syntax/logic errors; retries disabled.
2. `TRANSIENT_FAILURE`: Network timeouts or port races; retried up to `max_attempts` (default 2).
3. `INFRASTRUCTURE_FAILURE`: Missing binary/container; halts dependents.
4. `FLAKY_FAILURE`: Tracked across historical runs when alternating between `PASSED` and `FAILED`.

## 3. Node State Lifecycle

```text
[PENDING] ──(Dependencies met)──> [READY] ──(Dispatched)──> [RUNNING]
                                                              │
                    ┌─────────────────┬───────────────────────┼──────────────────┐
                    ▼                 ▼                       ▼                  ▼
                [PASSED]          [FAILED]                 [ERROR]           [TIMEOUT]
                                      │
                               (Cascade block)
                                      ▼
                                  [BLOCKED]
```
